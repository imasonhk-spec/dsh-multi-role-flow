## 环境与危险操作

> Windows 上没有 systemd，重启一律是 PowerShell 的进程级操作，误伤面比 Linux 更大。

| 禁止 | 原因 |
|---|---|
| `Stop-Process -Name python` / `taskkill /IM python.exe /F` | 杀掉所有 Python，含 DSH 运行时自身 |
| `Stop-Process -Name node` | 连带杀掉 Web 与工具链 |
| 重启整个服务栈 | 打断在途任务 |
| 按通配符或端口猜进程 | 宽泛匹配，容易误杀 |

正确做法：先用 `Get-NetTCPConnection -LocalPort {{PORT}}` 与 `Get-Process -Id {{PID}}` 定位到**具体 PID**，确认归属后再操作。只读查询（查端口、读日志、看版本）不算越界，但仍然不改、不装、不重启。

| V2 | 基线可复述 | 能说出实际运行的代码路径、版本、在途任务 ID 清单 | A | 路径无法确定时写「基线未知」，交 Lead 裁决，不猜 |
| V3 | {{CORE_CHAIN}} | {{CORE_CHAIN_RESULT}} | A 或 C | 需真实设备或真实账号：给出 3 步操作与观察点，列入待用户试用清单 |
| V4 | 权限与越权 | 越权请求被拒绝，无跨账号访问 | A | 无第二账号：写明「无法构造越权样本」，交用户用另一账号验证 |

| V6 | 受影响旧功能回归 | {{REGRESSION_RESULT}} | A 或 C | 需人工点击：给出操作路径与期望页面，交用户试用 |
| V7 | 证据与声明一致性 | 报告声明与证据逐条对得上，无截断、无矛盾 | B | 证据不足时有权质疑并要求补证，不自行重跑整套开发验收 |
| V8 | 上线门槛 | 「上线门槛」表 6 行全部由 ⬜ 改为 ✅（`N/A` 行写明理由），无剩余未验证项 | B | 任一条件无法核对：不予放行，交 Lead 决策 |
| V9 | 运行时版本握手 | 候选有 `runtime`（非 `null`）时：`flow.py handshake --id {{CANDIDATE}} --expect {{RUNTIME_VERSION}} --url {{HEALTH_URL}}` 退出码 0，且实际版本 == `manifest.runtime.version`；证据 `evidence/{{CANDIDATE}}/R1-handshake.md` 的「结果：pass」 | A | 健康检查不可达：记录 URL、HTTP 状态与错误原文，交用户确认服务已起或重启 DSH 后重跑；无 runtime 写 `N/A` 并注明「本次无运行时」 |
| V10 | 错误信息可定位 | 人为触发一次失败（错误方法 / 不存在路径 / 非法参数）：界面或日志必须出现 `HTTP <status> <METHOD> <path>（<code>）`；插件类三者齐全，禁止裸 `NOT FOUND` | A | 需真实点击：给出 3 步操作与期望文案，列入待用户试用清单 |
| V11 | 旧数据只读兼容（涉及持久化格式变更时） | 读旧数据在界面展示为新格式（如旧 Markdown 显示为纯文本）；`Get-FileHash -Algorithm SHA256` 证明原文件前后一致；证据含前后哈希与页面回执 | B | 无旧数据样本：写「无样本，未验证」，禁止宣称兼容 |

> `N/A` 规则：确实不适用时在「判定标准」列写 `N/A` 并注明原因；不写「通过」、不省略编号、不编造证据。

**证据分级**：A 命令原文 + 退出码；B 文件哈希与清单；C 截图 / 页面回执；D 自述。只有 D 的项一律记为「未验证」。

## 上线门槛

全部满足才放行（合取）：

| 条件 | 核对方式 | 状态 |
|---|---|---|
| V1—V7、V9—V11 有 A / B / C 级证据（`N/A` 项须注明理由，V8 由本表自检） | 逐项打开 `evidence/{{CANDIDATE}}/` 确认 | ⬜ |
| 阻断问题已解决 | 核对问题清单 | ⬜ |
| 待用户试用项已明确列出 | 核对 `DESIGN.md` 的「待用户试用项」 | ⬜ |
| 候选、安装顺序、回滚材料一致 | 核对 `manifest.json` 与 `INSTALL.md` | ⬜ |
| 目标无活动写入任务 | 实时检查进程与端口 | ⬜ |
| `runtime.requires_restart` 为 true 时：已重启 DSH，且重启后 `handshake` 退出码 0 | 核对 `RELEASE-REPORT.md`「运行时版本与重启」与 `evidence/{{CANDIDATE}}/R1-handshake.md` | ⬜ |

## 回滚条件

出现任一即回滚（析取）：入口无法进入 / 数据无法保存或出现跨账号访问 / 原有核心功能被破坏 / 实际加载与候选指纹不一致。

不触发回滚：仅效果不佳（慢、界面不理想）但数据安全与基础功能正常——记录问题交执行子智能体，不擅自扩大范围。

**回滚顺序不可颠倒**：① 保留新产生的数据与未知任务 ID ② 先关闭新入口 ③ 核实在途任务 ④ 最后恢复必要代码与配置。先恢复代码会让在途任务写进旧代码不认识的结构。
